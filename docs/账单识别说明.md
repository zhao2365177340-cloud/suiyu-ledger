# 账单识别说明

> 岁余的账单导入是**端侧能力**：截图在本机内存中做 OCR，文字在本机解析，任何图片与文本都不会上传到服务器。
> 本文说明支持哪些截图、解析规则如何工作、置信度怎么算，以及现在的已知限制。

## 一、支持的来源与格式

解析器按「来源关键词 + 金额锚点」识别，目前覆盖以下账单形态（`ocr/BillSamples.kt` 内置 12 条真实格式样例）：

| 来源 | 支持的页面 / 文本 | 样例 |
|---|---|---|
| 微信 | 账单详情（转账收入、消费） | `微信 · 转账收入详情`、`微信 · 消费详情` |
| 微信 | 收支明细列表（一张截图多笔） | `微信 · 收支明细列表` |
| 微信 | 红包收入 | `微信 · 红包收入` |
| 支付宝 | 账单详情（支付方式 / 收款方 / 账单分类 / 时间） | `支付宝 · 消费详情` |
| 支付宝 | 账单列表（多笔） | `支付宝 · 账单列表` |
| 支付宝 | 退款收入 | `支付宝 · 退款详情` |
| 银行 App | 信用卡 / 储蓄卡明细（消费、工资入账） | `银行 App · 信用卡消费`、`银行 App · 工资入账` |
| 银行短信 | 消费短信（尾号、时间、商户、余额） | `招商银行 · 消费短信` |
| 银行短信 | 工资入账短信（代发工资） | `招商银行 · 工资入账短信` |

支持的金额写法：`-25.00`、`+25.00`、`¥25.00`、`￥1,234.56`、`25.00元`、`1,234.56`。
支持的时间写法：`2026-11-20 12:31`、`2026/11/20`、`2026年11月20日 12:31`、`11月20日 12:31`、`11月20日`、`今天 / 昨天 / 前天`。
缺年份时按当年补全；如果补出来的日期明显在未来（例如当前是 11 月、截图写着「12月31日」），自动回退一年。

## 二、解析规则

`BillParser.parse(text, categories, nowMillis)` 是纯 Kotlin（不依赖 Android），流程如下：

1. **归一化**：全角转半角、`￥→¥`、`—/–/−→-`、合并多余空格、去空行。这样后面的正则只面对一种文本形态，也顺带修复 OCR 常见的全角符号。
2. **来源判定**（顺序有意义）：
   - 先看短信特征（`【xx银行】`、退订 / 致电 / 尾号 + 余额等）→ 短信；
   - 再看 `微信 / 零钱 / 财付通` → 微信，`支付宝 / 花呗 / 余额宝 / 借呗` → 支付宝；
   - 再看 `银行 / 信用卡 / 储蓄卡 / 尾号` → 银行 App；
   - 都没有 → 其他（仍会尝试解析）。
   银行短信里常出现「微信支付」字样，所以短信必须最先判，否则来源会错。
3. **找金额锚点**：逐行扫描 `AMOUNT_TOKEN`。带正负号、带货币符号、带「元」、或带两位小数的数字才算「金额」；日期里的 `2026-11-20`、时间 `12:31`、订单号、余额、优惠、尾号等数字全部排除。
4. **拆笔**：
   - 命中详情页特征词（`账单详情 / 当前状态 / 交易单号 / 创建时间 / 收款方 / 退款成功` 等）→ 视为一笔；重复出现的同额金额（如 `¥25.00` 与 `-25.00`）自动合并，优先取带符号的那个；
   - 否则每个金额锚点一笔，适合收支明细、账单列表这类一屏多笔的截图。
5. **方向（收入 / 支出）**：
   - 金额带 `+ / -` 号时以符号为准；
   - 强收入词（`转账-来自 / 退款成功 / 已存入零钱 / 入账 / 代发工资`）可以覆盖符号：OCR 把转账收入的 `+` 识别成 `-` 是常见错误，语义比符号可靠；
   - 其余按关键词打分：支出侧 `支付成功 / 消费 / 支出 / 扣款 / 转出 / 取现`，收入侧 `收款 / 到账 / 返还 / 报销 / 红包 / 收到`；
   - 「申请退款」是电商页面按钮，不当作收入；判断不到时默认按支出处理。
6. **日期 / 商户 / 账户**：
   - 日期优先取标签行（`创建时间 / 交易时间 / 转账时间 / 入账时间`），否则在金额附近找；
   - 列表场景按「上一条金额行 → 本笔金额行」区间找本笔的日期与商户，避免上一笔的日期/下一笔的商户被错配；
   - 商户依次取标签值（`收款方 / 商户名称 / 交易对方 / 商品说明 / 转账-来自`）、金额同行剩余文字（`美团外卖 -25.00`）、邻近行；
   - 账户取 `支付方式 / 付款方式 / 账户 / 卡号` 标签，银行文本再兜底到首行抬头（如「招商银行信用卡」）；短信从「尾号1234」拼出「招商银行 尾号1234」。
7. **分类映射**：只用传入的分类表（内置 + 自定义）的 `Category.keywords`，按**关键词长度降序**匹配，保证「美团单车 → 交通」而不是「美团 → 餐饮」；命中顺序是 商户 → 账单分类标签 → 上下文；都没命中按方向兜底到「其他 / 其他收入」。
   所以自定义分类只要配置了关键词，也会参与识别。
8. **置信度**：
   - 日期 + 金额 + 方向齐全：**0.9 起**（有商户 +0.04、金额带符号 +0.02，最高 0.99）；
   - 有日期但方向不明：0.78；
   - 缺日期：**0.6**；
   - 只有金额：**0.4**。
   置信度只是给用户看的「要不要细看」提示，不参与自动入账决策——所有草稿都要人工确认。
9. **结果输出**：`ParsedBill(source, type, amountCents, merchant, occurredAt, account, categoryId, confidence, rawText)`；金额恒为正的「分」，时间缺失为 `null`，按时间倒序。`ParsedBill.toRecord(memberId)` 可直接转成待入账的 `TxRecord`（id 由 `util/newId("t")` 生成）。

## 三、导入页面流程

`ui/screens/importer/ImportScreen.kt`（签名 `ImportScreen(onBack, onImported)`）分三步：

1. **选择来源**：顶部明确「截图仅在本机识别，不上传」；「选择账单截图」使用系统照片选择器（`ActivityResultContracts.PickMultipleVisualMedia(9)`，最多 9 张，不需要相册权限）；「粘贴短信 / 账单文本」用于银行短信。
2. **识别中**：逐张 ML Kit 中文 OCR，显示 `已完成 / 总数` 与进度条；每完成一张有轻触感，最后一张完成有成功触感。单张失败不会中断整批，页面会提示「N 张未识别出文字」，其余截图照常进入复核。
3. **草稿复核**：
   - 每张草稿可折叠；折叠时显示来源角标、置信度、日期、金额、分类、账户、疑似重复标记；
   - 展开后可改：方向（支出 / 收入）、金额（点金额或键盘图标）、分类（按方向过滤的下拉列表）、成员、日期（日历）、备注（可选）；
   - 重复检测调用 `LedgerRepository.findDuplicates`（同方向 + 同金额 + 3 天内 + 商户相近），命中会整卡高亮并标注「疑似重复 ×N」；
   - 底部「全选 / 取消」+「确认入账 N 笔」：只把勾选的草稿写入账本；用户改过分类的商户会通过 `commitImport(records, rules)` 写入「商户 → 分类」记忆规则，下次同一商户自动归类；
   - 入账成功播放 `HapticEffect.Wave` 并弹出结果（支出 / 收入笔数），点「完成」回调 `onImported(count)`。
4. **样例自测**：说明页底部有折叠区「样例自测」，一键把 12 条内置样例全部跑一遍并显示 `通过 / 失败`；它直接在设备上运行解析引擎，不联网。
5. **失败 / 空态**：识别不出文字、找不到金额时给出提示，并提供「重新选截图」和「手动补录」出口（回首页点「记一笔」）。

## 四、隐私说明

- 截图只通过 ML Kit 内置中文模型在本机做 OCR，**不联网、不上传、不经过任何服务器**；
- 识别文字只在内存中传给解析器，入账结果写入本机 `filesDir/ledger.json`；
- 页面不申请相册读写权限（使用系统照片选择器），也不会保存原始截图；
- 「样例自测」同样完全在本机运行。

## 五、已知限制

1. **一张截图多笔列表**：依赖 OCR 的「日期 / 商户 / 金额」行序。目前覆盖主流 App 的两种行序（日期→商户→金额、商户+金额→日期），但极端错行（如金额与日期跨列粘连）仍可能漏笔或错配日期——可在草稿里手动改。
2. **同一商户同一天同金额的两笔真实消费**可能被批次内去重合并；解析详情页时重复金额也会合并。属于「宁少勿重」的取舍，可手动补录。
3. **银行短信一次只解析一笔**：短信里通常只有一笔交易；如果一次粘贴多条短信，只取第一条能识别的交易。
4. **分类依赖关键词**：关键词没覆盖到的商户会落到「其他 / 其他收入」；可在导入页改一次，规则会记住该商户。
5. **表情 / 特殊字体截图**：ML Kit 对手写、艺术字、极低分辨率截图识别率有限，建议用系统截图原图。
6. **不支持**：账单 Excel/CSV、PDF 对账单、境外多币种账单（外币金额会被当作人民币展示）、分期/手续费拆分明细。
7. **日期缺时间**时默认中午 12:00，仅用于展示与排序，不影响按日统计；日期缺失的草稿默认填「今天」，用户可改。
8. 解析器不做金额校验（例如「支出 -25.00」与「收款方」矛盾时按强语义优先），因此**入账前请扫一眼草稿**。
