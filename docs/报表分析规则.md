# 岁余 · 报表分析规则

> 本文件说明「统计」「报表」两个页面里每一个数字的**来源、公式与边界**，以及自动洞察文案的生成规则。
> 目的：同一笔钱在首页、统计、报表、成员分析里必须得到同一个数字；换一个页面看到不同的数，就是 bug。
>
> 实现位置：
> - 页面：`app/src/main/java/com/suiyu/ledger/ui/screens/stats/`、`app/src/main/java/com/suiyu/ledger/ui/screens/report/`
> - 计算引擎（公共文件，本模块只调用、不修改）：`analytics/Analytics.kt`
> - 自动文案（公共文件）：`analytics/Narrative.kt`

---

## 1. 统一口径（所有页面共用的前提）

| 规则 | 说明 |
|---|---|
| 统计范围 | 只统计 `TxRecord.includeInStats = true` 的流水；内部转账等可置为 `false` 的记录在任何页面都不出现。 |
| 账期 | 自然月，按**设备本地时区**划分，区间为 `[当月 1 日 00:00, 下月 1 日 00:00)`；跨年由 `MonthKey.plusMonths` 处理，不使用字符串排序。 |
| 金额单位 | 全链路 `Long`（分）；展示时经 `Money.format / plain / percent / compact`，图表组件统一收 `Float` 表示的分。 |
| 方向 | `TxType.EXPENSE` 为支出、`TxType.INCOME` 为收入；结余 = 收入 − 支出。 |
| 比率分母为 0 | 返回 `null` / 0，展示为「—」，绝不出现 `NaN%`。 |
| 日均 | 本月 = 支出 ÷ 当月**已过天数**（今天几号）；历史/未来月 = 支出 ÷ 当月总天数。该规则由 `Analytics.summary.avgDailyExpenseCents` 定义。 |
| 成员口径 | 成员维度的过滤条件与 `Analytics.memberSlices / categorySlices(memberId=…)` 一致：按 `record.memberId` 过滤；成员被删除后其流水已由仓库归到「我」。 |
| 隐私遮罩 | `settings.privacyMask = true` 时，页面上的金额文本统一替换为 `¥ ••••`；图表组件内部点选读数不受该开关控制（公共组件限制，见 §7）。 |

## 2. 统计页（`StatsScreen`）

### 2.1 页面控件与数据切片

页面状态：账期 `month`、方向 `type`（支出/收入）、视角 `memberId`（`null` = 家庭，否则某成员）、分段 `结构 / 对比 / 日历`。

- 家庭视角：所有数字直接调用 `Analytics` 的公开函数（`summary`、`categorySlices`、`comparison`、`monthPoints`、`dailyPoints`、`healthMetrics`）。
- 成员视角：统计引擎暂未提供「成员汇总」公开函数，因此先把当月记录按 `memberId` 预过滤，再交给同一批 `Analytics` 函数计算。过滤条件与 `Analytics.memberSlices`、`categorySlices(memberId=…)` 完全一致，**不新造口径**。
  - 这是本模块唯一一处「页面侧裁剪」，未来 `Analytics` 若补充 `memberSummary(records, month, memberId)`，应替换为直接调用该函数。

### 2.2 结构

| 指标 | 公式 / 来源 |
|---|---|
| 本期总额 | `Analytics.summary(...)` 的 `expenseCents` / `incomeCents` |
| 笔数 | `summary.expenseCount` / `summary.incomeCount` |
| 日均 | 支出：`summary.avgDailyExpenseCents`；收入：`summary.incomeCents ÷ 本期天数`（与日均支出一致的天数口径，见 §1） |
| 分类占比 | `Analytics.categorySlices(records, categories, month, type, memberId)`：`ratio = 该分类合计 ÷ 本期同类型合计`，按金额降序 |
| 中心总额 | 与「本期总额」同源，保证环形图中心与顶部数字一致 |

点击扇区 / 分类排行 → 底部面板列出该分类当月明细（`SyRecordRow`），排序沿用仓库中流水的时间倒序。

### 2.3 对比

1. **本月 vs 上月（`GroupedBarChart`）**
   - 按分类：`Analytics.categorySlices(..., baseMonth = month.plusMonths(-1))`，取「本月金额、上月金额」较大者排序前 6 类。柱子为 `本月 / 上月` 两期，金额单位分。
   - 按成员：`Analytics.memberSlices` 分别计算本月与上月，每个成员一组柱（`本月 / 上月`），过滤掉两期都为 0 的成员。
   - 差值徽标：`Change(current, base)`，`pct = (current − base) ÷ base`（`base = 0` 时显示「上月无数据」，不显示百分比）。
   - 颜色语义：收入视角「上涨 = 好」，支出视角「下跌 = 好」；颜色取 `SyTheme.colors.positive / negative`。
2. **近 6 / 12 个月趋势（`TrendChart`）**
   - 家庭：`Analytics.monthPoints(records, month, count)`；成员：`Analytics.memberMonthPoints(records, memberId, month, count)`。
   - 两条线分别为支出、收入；月份标签用 `MonthKey.short()`（如「11月」）。
   - 点按节点读出该月「支出 / 收入 / 结余」。

### 2.4 日历

- 热力值：`Analytics.dailyPoints(scopedRecords, month).map { expenseCents }`，即当月**每天支出**；成员视角按成员预过滤，与 §2.1 的裁剪一致。
- 颜色深度：以当月单日最大支出为 100%，线性映射到 `expense` 色的透明度（0.12 → 0.84）；零支出日显示浅灰底。
- 指标卡：
  - 日均支出：`healthMetrics.avgDailyExpenseCents`；
  - 最大单笔支出：`healthMetrics.largestExpense`（当月支出金额最大的一笔；同日多笔时取遍历中的最大者）；
  - 零支出天数：`healthMetrics.noSpendDays = 当月总天数 − 有支出记录的天数`。
- 点按某天 → 底部面板列出当天该视角下的全部流水，并给出当日支出/收入合计。

## 3. 报表页（`ReportScreen`）

阅读顺序：抬头与总述 → 总览 → 收支结构 → 环比 → 同比 → 成员分账 → 财务健康 → 自动洞察 → 分享 / 个税测算。

### 3.1 总述

`Narrative.overview(comparison, familyName)` 生成，`familyName` 来自 `AppGraph.ledger.settings.familyName`。
文案包含：当月笔数、收入、支出、结余、结余率；若有上月/去年同月基准，再补一句环比、同比结论。当月无记录时给引导文案。

### 3.2 四宫格总览

| 卡片 | 数值来源 | 环比 | 同比 |
|---|---|---|---|
| 收入 | `comparison.current.incomeCents` | `comparison.incomeMoM` | `comparison.incomeYoY` |
| 支出 | `comparison.current.expenseCents` | `comparison.expenseMoM` | `comparison.expenseYoY` |
| 结余 | `current.balanceCents = income − expense` | `comparison.balanceMoM` | 页面按同口径构造 `Change(current.balanceCents, lastYear.balanceCents)` |
| 结余率 | `current.savingsRate = 结余 ÷ 收入`（收入为 0 时按 0 处理） | `comparison.savingsRateDelta`（百分点） | `current.savingsRate − lastYear.savingsRate`（百分点） |

- 变化徽标：`↑ / ↓ + 百分比`；`base = 0` 或 `base < 0`（结余等可能出现负基准）时相对百分比会失真，统一显示「— 无基准」；正负色按「对家庭是否有利」判定（支出上涨记为负向，收入/结余/结余率上涨记为正向）。
- **结余率的变化以百分点（pp）计**，不是相对百分比：`pp = (本月结余率 − 基准结余率) × 100`，避免「结余率从 10% 到 12% 被读成增长 20%」的歧义。
- 当月收入为 0 时结余率没有分母，结余率卡片显示「—」；环比/同比仍按各自的基准月判断有无基准。
- 同比基准没有收入（`lastYear.incomeCents = 0`）时，结余率同比显示「— 无基准」。

### 3.3 收支结构

- `Analytics.categorySlices(records, categories, month, EXPENSE)`（家庭视角，支出）。
- 环形图中心为当月支出总额；下方排行取前 5 类，同时给出「共 n 个分类、前三类合计占比」。
- 排行条长度 = `ratio`（分类占比），金额与占比同时展示，避免只靠长度误读。

### 3.4 环比分析（分类变化 Top 5）

- 来源：`Analytics.categoryChanges(records, categories, month)`，按 `|本月 − 上月|` 降序。
- 展示：本月、上月金额、差额（带符号）、变化百分比；`上月 = 0` 显示「上月无此类」，`本月 = 0` 显示「本月为 0」。
- 颜色：多花为 `negative`（朱砂），少花为 `positive`（青玉）。

### 3.5 同比分析

- 基准月：`MonthKey(month.year − 1, month.month)`；数据来自 `comparison.lastYear`。
- `GroupedBarChart` 两组（支出、收入），「本月 / 去年同月」两根柱；下方逐行给出「去年同月 → 本月」金额与 `expenseYoY / incomeYoY / 结余同比` 徽标。
- 结余同比：`Change(current.balanceCents, lastYear.balanceCents)`，与四宫格同一口径。

### 3.6 成员分账与成员单独分析

- 成员分账：`Analytics.memberSlices(records, members, month)`，按支出降序；每人一行展示头像/身份、支出、收入、占比（`该成员支出 ÷ 家庭总支出`，家庭支出为 0 时显示「—」）、结余（可负）与占比进度条。
- 点按展开「个人分析」（由 `expandedMemberId` 状态驱动的条件渲染，同时只展开一个成员）：
  - 近 6 个月走势：`Analytics.memberMonthPoints(records, memberId, month, 6)`，支出 + 收入两条线；
  - 主要支出分类：`Analytics.memberCategorySlices(records, categories, memberId, month, EXPENSE)` 取前 4。
  - 若近 6 个月记录不足或本月无支出，给出对应空态文案，不伪造数据。
- 成员视角的合计与家庭合计同源：家庭支出 = 各成员支出之和（同一批 `includeInStats` 流水）。

### 3.7 财务健康（`Analytics.healthMetrics`）

| 指标 | 公式 / 定义 |
|---|---|
| 结余率 | `结余 ÷ 收入`；收入为 0 时页面显示「—」（分母为 0，不展示 0.0%） |
| 刚性支出占比 | `固定支出 ÷ 本月支出`；固定支出 = 分类 id 属于 `cat_housing`（居住）、`cat_telecom`（通讯）、`cat_education`（教育）的支出合计；页面上的「约 ¥x」= 本月支出 × 该占比；本月支出为 0 时显示「—」 |
| 零支出天数 | 本月总天数 − 有支出记录的天数（≥ 0） |
| 最大单笔支出 | 本月支出金额最大的一条流水，展示日期、分类、成员与商户 |
| 结余率评级 | ≥ 30% → 健康；10%–30% → 尚可；0–10% → 偏低；< 0 → 支出超过收入 |

> `healthMetrics` 还提供 `expenseToIncome / topCategoryRatio / passiveIncomeRatio / savingsRating`，本页只展示上述四项，其余字段供其他页面复用。

### 3.8 自动洞察

由 `Narrative` 三个函数拼接，全部是**可被数字核对的陈述句**，不做道德评价、不给投资建议：

1. `Narrative.categoryInsights(slices, changes)`（最多 3 条）
   - 结构：最大支出分类及其占比；占比 > 35% 时标记为关注（negative tone）；
   - 波动：排除占比第一后变化绝对值最大的分类，说明多花/少花金额与百分比；
   - 集中度：支出前三类合计占比（分类数 ≥ 3 时生成）。
2. `Narrative.memberInsights(memberSlices, summary)`（最多 2 条）
   - 成员：支出最高的成员及其家庭占比、收入、个人结余；
   - 均衡：可分析成员（支出 > 0）人均支出与最高/最低差额。
3. `Narrative.healthInsights(health, summary)`（最多 3 条）
   - 健康：结余率评级与一句话说明（≥30% 正向 / 10–30% 中性 / 0–10% 负向 / <0 负向）；
   - 刚性：固定支出占比与对应金额；
   - 节奏：零支出天数与日均支出。

tone → 视觉：`POSITIVE` 青玉、`NEUTRAL` 稻金、`NEGATIVE` 朱砂；左侧色条 + emoji 同步使用，保证不只靠颜色传达含义。

### 3.9 分享与个税入口

- 顶部「分享」与底部「分享这份报表」调用同一份文本：
  `Share.shareText(context, Narrative.reportText(comparison, categorySlices, memberSlices, health, familyName))`。
  文本包含：标题、总述、收支结构前 6 类、成员分账（有记录的成员）、财务健康四项、署名。
- 「个税测算」按钮调用页面入参 `onOpenTax()`，由 nav 打开税务页（本模块不持有税务逻辑）。

## 4. 图表与交互约定

| 组件 | 数据来源 | 交互 |
|---|---|---|
| `DonutChart` | 分类 slices（分，Float） | 点按扇区有选中态（其他扇区变淡）与 Tick 触感；统计页会打开分类明细面板 |
| `ChartRankList` | 分类 slices | 点按行 Tick 触感；统计页打开明细面板 |
| `GroupedBarChart` | `BarGroup(本月, 上月/去年同月)` | 点按柱组有选中读数（内置）；页面追加「本月/上月/差额」明细行 |
| `TrendChart` | `LineSeries(支出, 收入)` | 点按节点有选中态 + Tick 触感；页面追加该月明细行 |
| `MonthHeatmap` | 当月每日支出 | 点按某天打开当日流水面板 |
| `Sparkline / SyProgressBar` | 趋势 / 占比 | 只读展示 |

图表数值单位统一为**分（Float）**，由 `Money.format` 生成标签，避免浮点金额漂移。

## 5. 空数据规则

- 统计页：整月无记录 → 保留月份/视角/分段控件，内容区 `SyEmpty` 引导「导入账单或手动记一笔」；仅当前方向（支出/收入）或当前成员无数据 → 卡片内给出对应空态文案，不显示空图表。
- 报表页：整月无记录 → 抬头 + `Narrative.overview` 引导文案 + `SyEmpty`（含「导入账单一键开始」提示）+ 分享/个税入口；有记录但某分类/成员/同比基准缺失 → 局部空态，不生成假数据。

## 6. 可复现的核对方法

1. 用示例数据启动 App → 统计页「支出 · 家庭」：
   - 顶部「本期支出」应等于报表页四宫格「支出」；
   - 环形图中心金额应等于分类排行金额之和；
   - 分类排行占比之和应约为 100%（四舍五入误差 ≤ 1%）。
2. 报表页「结余」应等于「收入 − 支出」；「结余率」应等于「结余 ÷ 收入」。
3. 成员分账各成员支出之和应等于家庭支出（同一账期、同一 `includeInStats` 过滤）。
4. 同比/环比在基准月无数据时，必须显示「— 无基准」而不是 0% 或 NaN。

## 7. 已知局限与后续可改进项

1. **成员视角的汇总函数缺失**：`Analytics` 没有按成员返回 `MonthSummary` 的公开 API，统计页采用「先按成员过滤记录、再调用 `summary/healthMetrics`」的方式；公式与家庭视角一致，但属于页面侧裁剪。建议后续在公共分析层补 `memberSummary(...)`。
2. **日均收入**：`Analytics.summary` 只提供 `avgDailyExpenseCents`；收入视图的日均按同一公式（收入 ÷ 本期天数）换算，若未来分析层补充 `avgDailyIncomeCents`，应改为直接调用。
3. **分类环比柱状图只覆盖「本月存在的分类」**：上月有、本月为 0 的分类不会出现在柱状图中（文字「环比分析 Top5」会完整展示这类变化）。这是为了让柱子数量可控，不是数据丢失。
4. **隐私遮罩的图表读数**：`GroupedBarChart / TrendChart` 内置的点选读数由公共组件生成，不读取 `settings.privacyMask`，开启隐私模式时图表内读数仍会显示原始金额；页面上的金额卡片与排行已遮罩。后续可由组件层统一接管。
5. **总述段落为纯文本**：`Narrative.overview` 文案中含金额，隐私模式下不做逐词遮罩（分享出去的文本也包含金额，由用户主动发起）。
6. **图表浮点精度**：图表组件使用 `Float` 表示「分」，超大金额（> 2^24 分 ≈ 16.7 万元）在像素映射时可能有极小误差；页面文字数字始终用 `Long`，不受影响。
7. **同比仅支持「去年同月」**：`Analytics.comparison` 固定取 `month.year - 1` 的同一自然月，不提供自定义同比区间。
8. **洞察文案是模板句**：由 `Narrative` 根据阈值生成，不包含预测、投资建议或外部数据；不同月份可能重复出现相似句式。
9. **跨设备/多账本**：数据为单机 `filesDir/ledger.json`，报表口径不涉及汇率、跨账本合并或多币种。
10. **报表为纯文本分享**：当前不生成图片或 PDF；若后续需要，可基于同一份 `Analytics` 结果渲染，不可另算口径。
